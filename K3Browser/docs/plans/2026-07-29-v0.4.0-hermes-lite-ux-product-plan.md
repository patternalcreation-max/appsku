# K3Browser v0.4.0 Hermes-Lite UX/Product Execution Plan

> **Mode:** operator cockpit, iPhone-first, sideload-safe.  
> **Goal:** ubah v0.3.1 dari browser + agent sheet menjadi **agent cockpit**: page tetap full, command ada di bawah, agent loop terlihat, risky action selalu approval, hasil bisa disimpan/export.

## 0) Product stance

**Tagline internal:** “Hermes-Lite in your browser: observe, ask, approve, act, save.”

**Native maksimum yang boleh masuk v0.4.0:**
- SwiftUI cockpit shell di atas `WKWebView`.
- `WKWebView.evaluateJavaScript` untuk observe/click/fill/scroll/navigation.
- Keychain untuk API key.
- `UserDefaults`/JSON file sandbox untuk memory/run log.
- `UIPasteboard` hanya lewat tombol eksplisit.
- `UIActivityViewController` untuk export/share.

**Browser-support only seperti Hermes:** tidak perlu extension, App Groups, VPN, Autofill extension, background crawler, iCloud, push, widget, Safari extension, NetworkExtension, private API.

## 1) UX target: dari v0.3.1 ke v0.4.0

### Current v0.3.1
- Top URL bar selalu dominant.
- Agent dibuka via sheet.
- Sheet punya tabs: `Ask`, `Snapshot`, `Tools`, `Settings`.
- Tools manual: fill/click/custom JS.

### v0.4.0 desired feel
- Page jadi canvas utama.
- Agent cockpit selalu reachable dari **bottom command bar**.
- Agent bukan tab chat; agent punya loop state: `Observe → Think → Request approval → Execute → Done`.
- Approval tray muncul di bawah, bukan fullscreen modal.
- Timeline action selalu visible di cockpit.
- Suggested chips bikin demo cepat terasa hidup.
- Memory/save/export bikin hasil agent terasa punya output nyata.

## 3) Cockpit surfaces

### A. Bottom command bar — daily use
**Purpose:** quick ask/run without opening sheet.

Flow:
1. User taps input.
2. Keyboard opens; bottom bar lifts via safe-area/keyboard behavior.
3. User types task: `Find the search box and search for K3Browser`.
4. Tap `Run`.
5. Bar switches to compact status row + `Stop`.
6. If risky action proposed, approval tray appears above command bar.

Implementation task:
- Add `@State private var commandText = ""` in `BrowserView`.
- Add `bottomCommandBar` overlay using `.safeAreaInset(edge: .bottom)` where possible; for iOS 15 use `VStack { Spacer(); ... }.ignoresSafeArea(.keyboard, edges: .bottom)` carefully.
- Do not let bar cover page controls: add bottom padding/overlay only; user can scroll page behind.

Acceptance:
- On iPhone 15/SE widths, input and buttons do not clip.
- Keyboard does not hide command input.
- Agent is runnable without opening old sheet.

### B. Agent cockpit sheet — replace old tabs
Old `AgentPanel` segmented tabs should become one cockpit scroll, not four permanent tabs.

Sheet detents if available:
- iOS 16+: `.presentationDetents([.fraction(0.42), .large])`
- iOS 15 fallback: normal sheet.

Sections in order:
1. **Status header**
   - Title: `K3 Agent`
   - Subtitle examples:
     - `Ready on duckduckgo.com`
     - `Thinking · step 2/6`
     - `Waiting for approval`
     - `Stopped by operator`
2. **Suggested actions** chips.
3. **Command** TextEditor + `Run` / `Stop`.
4. **Approval tray preview** if pending.
5. **Action timeline**.
6. **Memory / export** row.
7. **More** collapsed section for Snapshot, Tools, Settings.

Exact labels:
- Header title: `K3 Agent`
- Header subtitle idle: `Ready on {host}`
- Step text: `Step {n}/{max}: {phase}`
- Empty timeline: `No actions yet. Run a command to start.`
- More section label: `More tools`
- Settings row: `API & model`

### C. Approval tray
**Never fullscreen. Never approve all. One action at a time.**

Exact copy:
- Title: `Approve action?`
- Subtitle format: `{toolLabel} on {host}`
- Selector row: `Target: {selector}`
- Value row for fill: `Value: {maskedOrPlain}`
- Risk row:
  - click: `Risk: page click`
  - fill: `Risk: writes into page`
  - submit: `Risk: form submit`
  - cross-domain nav: `Risk: leaves current site`
- Buttons:
  - Primary: `Run once`
  - Secondary: `Edit`
  - Destructive/neutral: `Deny`

Tool labels:
- `click_selector` → `Click`
- `fill_selector` → `Fill field`
- `submit_form` → `Submit form`
- `open_url` same-domain → `Open URL`
- `open_url` cross-domain → `Open external site`
- `scroll` → `Scroll page`

Closed/timeout behavior:
- Closing tray = deny.
- Stop Agent = deny pending action + cancel run.
- Late approval after run cancelled must fail closed: timeline item `Denied — run stopped`.

### D. Action timeline
Timeline item format:
- Observe: `👁 Observed page · {chars} chars, {links} links, {controls} controls`
- Thought: `💭 Plan · {short text}`
- Proposed: `⏸ Needs approval · {toolLabel}`
- Approved: `✅ Approved · Run once`
- Executed: `⚙️ Ran {toolName} · {result}`
- Saved: `💾 Saved note · {filename}`
- Error: `⚠️ Error · {message}`

Each item has timestamp small text: `16:42:10`.

Timeline quick actions:
- `Copy log`
- `Export MD`
- `Clear`

### E. Memory / save / export
MVP memory is local and simple.

Exact row labels:
- `Save note`
- `Copy answer`
- `Export run`

Storage target:
- App sandbox `Documents/K3Browser/Notes/`
- File names:
  - note: `yyyy-mm-dd-host-note.md`
  - run: `yyyy-mm-dd-host-run.md`

Copy for save success:
- `Saved to K3Browser/Notes`

Do not build complex memory DB yet. JSON/Markdown enough for v0.4.0.

## 4) Agent loop product behavior

### Minimal loop states
Create an enum conceptually:

```swift
enum AgentPhase {
    case idle
    case observing
    case thinking
    case awaitingApproval(ApprovalRequest)
    case acting(String)
    case done
    case stopped
    case error(String)
}
```

### Step loop
Max default: `6` steps.

Loop:
1. `observe`: capture snapshot.
2. `think`: ask model for either answer or tool call JSON.
3. If answer only: append timeline, done.
4. If read-only tool: auto-run.
5. If risky tool: enqueue approval tray.
6. On `Run once`: execute one action, observe again.
7. On `Deny`: append deny, ask model for alternative or stop.
8. On `Stop`: cancel all.

### Tool risk policy v0.4.0
Auto-run:
- `snapshot_page`
- `extract_links`
- `extract_text`
- `save_note` after explicit user asked save/export

Approval required:
- `click_selector`
- `fill_selector`
- `submit_form`
- `open_url`
- `scroll` if agent-initiated during a loop; optional to auto-run later
- `copy_to_clipboard`
- `share/export` unless user tapped button directly

Hard block:
- password fields unless user typed exact intent
- payment/crypto/delete/account settings keywords
- file upload

Blocked copy:
- `Blocked: sensitive action needs manual control.`

## 7) Wow demo scenario

### Demo page
Use DuckDuckGo or any simple search page.

### Script
1. Launch K3Browser.
2. Bottom bar shows `● Ready` and placeholder `Tell K3 what to do…`.
3. Type: `Find the search box and search for K3Browser Hermes Lite.`
4. Agent timeline:
   - `👁 Observed page · ... controls`
   - `💭 Plan · Fill the search box, then submit search.`
   - `⏸ Needs approval · Fill field`
5. Approval tray:
   - `Approve action?`
   - `Fill field on duckduckgo.com`
   - `Target: input[name="q"]`
   - `Value: K3Browser Hermes Lite`
   - buttons `Run once`, `Edit`, `Deny`
6. Tap `Run once`.
7. Next tray asks `Click` or `Submit form`.
8. Tap `Run once`.
9. Page navigates to results.
10. Tap chip `Summarize`.
11. Agent summarizes results.
12. Tap `Save note` → status `Saved to K3Browser/Notes`.
13. Tap `Export run` → ShareSheet opens.

### Why this wows
- Native browser actually acts.
- User sees safety gate.
- Timeline proves loop.
- Output becomes saved/exportable artifact.

## 9) What not to add yet

Do not add in v0.4.0:
- Multiple tabs/session restore.
- Bookmarks/history UI.
- Downloads manager.
- OCR/Vision.
- PDF export.
- Workflow editor/recipe marketplace.
- Hermes relay mode.
- Background monitoring.
- Any extension target.
- Autofill credential provider.
- App Groups / entitlements.
- Auto-approval session/batch approve.
- Payment/login/crypto automation.
- Swipe between cockpit tabs; conflicts with iOS gestures.
- Transparent idle panel; hurts legibility.
